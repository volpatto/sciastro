# Content and page organization

For explicit pages, reusable sections, custom paths and LNCC Theme, see
[Pages, themes and extensions](customization.md). The automatic mode below remains supported.

Start from a project generated by `sciastro init`. Content lives in `content/`
unless you choose another directory with `contentDir`.

## Home and About

`kind: group` uses **Home** (**Início** in Portuguese); `kind: individual` uses
**About** (**Sobre**). The name, description, affiliation, languages and theme
belong in `sciastro.yaml`. The introduction is the Markdown file referenced by
`home.body`.

Keep the introduction brief. Detailed descriptions belong on the Research page.
Homepage cards are generated from `research.yaml`, so you do not maintain a second
copy of each research summary.

## Research

Each entry in `research.yaml` creates a homepage card and a Research section:

```yaml
- id: numerical-methods
  title:
    pt: Métodos numéricos
    en: Numerical methods
  summary:
    pt: Métodos para modelos de transporte e escoamento.
    en: Methods for transport and flow models.
  body:
    pt: research/numerical.pt.md
    en: research/numerical.en.md
```

`id` supplies the anchor, such as `/research/#numerical-methods` on an English-only
site. Keep it stable to preserve links. `summary` is plain text, limited to 240
characters per language. The Markdown in `body` supports explanations, lists,
figures and citations.

An optional figure belongs in the same entry:

```yaml
  image:
    src: /images/result.png
    alt:
      pt: Descrição do resultado representado.
      en: Description of the result shown.
```

Place the image in `public/images/result.png`. Check usage rights and add attribution
when required. The build checks that declared local images exist.

## Team and supervision

`team.yaml` supplies the **Team** page for groups and **Supervision** for individuals.
Each person has one record:

```yaml
- id: maria-example
  name: Maria Example
  role: student
  status: active
  level: masters
  startYear: 2026
  affiliation: Example University
  topic:
    pt: Discretização de modelos de transporte
    en: Discretization of transport models
```

| Field | Values / behavior |
| --- | --- |
| `role` | `faculty`, `researcher`, or `student` |
| `status` | `active` or `alumni` |
| `level` | Required for students; must match a configured level |
| `startYear`, `endYear` | Optional; active members must not have an end year |
| `affiliation`, `topic` | Optional shared or translated text |
| `photo` | Optional `src` and `alt`, as for research figures |
| `links` | Optional list of objects with `label` and `url` |

Active faculty appear first, followed by active researchers and active students
organized by level. Alumni appear in a separate section regardless of their former
role. Empty sections are hidden.

When a student finishes, change `status` to `alumni` and add `endYear`. Keep `level`
to show the completed degree. That person automatically leaves the active list.

Default levels are `undergraduate`, `masters`, `phd`, and `postdoc`. To customize
them, define the **complete list** in `sciastro.yaml`; list order determines display order:

```yaml
studentLevels:
  - id: undergraduate
    label: { pt: Iniciação científica, en: Undergraduate research }
  - id: masters
    label: { pt: Mestrado, en: Master’s students }
  - id: phd
    label: { pt: Doutorado, en: Doctoral students }
  - id: internship
    label: { pt: Estágio, en: Internships }
```

Use `role: researcher` for postdoctoral researchers if that fits your group;
the schema does not require treating them as students. Person, research-area and
level identifiers must be unique within their respective lists.

## Additional pages

Register extra pages in `pages.yaml`, in navigation order:

```yaml
- slug: projects
  title: { pt: Projetos, en: Projects }
  icon: lucide:folder-open
  body: { pt: projects.pt.md, en: projects.en.md }
```

`slug` stays the same in both languages. With Portuguese as the default, this
example generates `/projects/` and `/en/projects/`. Built-in pages have localized
paths, such as `/pesquisa/` and `/en/research/`.

Use additional pages for teaching, software, partnerships, CV and contact. The
optional `icon` defaults to `lucide:file-text`; see the [icon guide](icones.md) for
menu overrides and language flags.

Downloadable files belong in `public/`. For example, link to
`public/files/cv.pdf` with `[Curriculum vitae](/files/cv.pdf)`.

Internal Markdown links start with `/`, without the hosting subdirectory. The
generator adds `base` automatically. External links use `https://`. Markdown
supports headings, lists, links, tables, images and code blocks. Raw HTML is
rendered as text rather than executed.

## Themes, logo and profile links

Choose `theme: classic`, `theme: modern` or `theme: lncc`. Visitors can switch between light and
dark modes. The initial choice follows the system; an explicit choice is saved
in the browser.

An optional logo in `sciastro.yaml` replaces the default geometric mark:

```yaml
logo:
  src: /images/logo.svg
  alt: Research group name
links:
  - label: GitHub
    url: https://github.com/your-group
  - label: ORCID
    url: https://orcid.org/0000-0000-0000-0000
```

Replace the example identifiers and URLs with real ones. To validate a generated
website before building, run `pixi run pnpm check` in its directory. Validation
errors identify the relevant file and field.
